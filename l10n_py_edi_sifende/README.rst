Conector de `Sifende <https://sifende.com.py>`__ para la facturación
electrónica de Paraguay.

Registra a Sifende como proveedor dentro de ``l10n_py_edi_base``. Odoo
sigue numerando las facturas y armando los datos del documento; Sifende
firma el XML, lo envía a SIFEN y devuelve el resultado y el KuDE. No
hace falta cargar certificado, CSC ni la librería ``sifen`` en Odoo.

Documentos admitidos: factura (FE), nota de crédito (NCE), nota de
débito (NDE), nota de remisión (NRE) y autofactura (AFE).

El envío es asincrónico. Al enviar, el documento queda en estado
«Procesando» con su CDC y su QR. Sifende avisa por webhook cuando SIFEN
responde, y un cron que consulta cada 5 minutos sirve de respaldo;
cuando SIFEN aprueba, el documento queda «Aceptado» con el XML firmado y
el KuDE adjuntos.

Configuration
=============

1. En Sifende, cree una API key del ambiente que corresponda (Sandbox,
   Pruebas o Producción).
2. En *Facturación electrónica > Conectores*, cree un conector con
   proveedor **Sifende**. Solo se admite un conector por empresa.
3. Elija el ambiente del conector (*Pruebas* o *Producción*), pegue la
   API key y, si usa un entorno propio de Sifende, cambie la URL base
   (HTTPS; HTTP solo se admite para ``localhost``). La API key y la URL
   base solo las ven y editan los administradores (*Ajustes*): la URL
   decide adónde viaja la clave.
4. Pulse **Probar Conexión**. Falla si el ambiente del conector no
   coincide con el de la API key, y advierte si el timbrado, el
   establecimiento o el punto de expedición de Odoo no existen en
   Sifende.
5. Cargue en Sifende el mismo timbrado que usa Odoo. Se recomienda un
   punto de expedición exclusivo para Odoo: Sifende acepta el número de
   documento que manda Odoo y rechaza los que ya están en uso.
6. Opcional: en *Inventario > Configuración > Unidades de medida*,
   ajuste el *Código de unidad de medida SIFEN* de cada unidad (por
   defecto 77, unidad).
7. Opcional pero recomendado: pulse **Registrar webhook** para que
   Sifende avise a Odoo apenas SIFEN responde, sin esperar al cron. Odoo
   debe ser accesible desde Internet por HTTPS y su URL base
   (``web.base.url``, en *Ajustes > Técnico > Parámetros del sistema*)
   debe ser la pública: Sifende rechaza ``http`` y las direcciones
   locales. El botón registra
   ``<web.base.url>/l10n_py_edi_sifende/webhook/<id del conector>`` para
   los eventos ``documento.aprobado``, ``documento.rechazado`` y
   ``documento.cancelado``, y guarda el secreto de firma, que solo ven
   los administradores. Si la URL ya estaba registrada en Sifende, el
   botón lo informa y hay que pulsar **Rotar secreto** para obtener un
   secreto. **Quitar webhook** lo elimina en Sifende. Cada aviso solo
   dispara una consulta del estado vigente en Sifende, así que un aviso
   atrasado no pisa el estado real. El cron sigue activo como respaldo.
8. Con varias bases de datos en el mismo servidor, la URL pública debe
   resolver a la base correcta (``dbfilter`` o el subdominio), porque
   Sifende no envía el nombre de la base.
9. Permisos. Cada conector solo se opera desde su empresa. Enviar,
   reintentar y cancelar un documento exige el rol *Contabilidad >
   Facturación* y poder editar el documento; consultar su estado,
   también el de solo lectura. *Inutilizar números* y **Probar
   Conexión** son del *Contabilidad > Administrador*. La API key, la URL
   base y el webhook son de *Ajustes*.

Usage
=====

1. Confirme la factura y pulse **Enviar a EDI**. El documento pasa a
   *Procesando*.
2. El estado se actualiza solo: *Aceptado* con el XML y el KuDE
   adjuntos, o *Rechazado* con los mensajes de SIFEN en el campo
   *Mensaje EDI*. Si el webhook está registrado, Sifende avisa a Odoo en
   cuanto SIFEN responde; si no, o si el aviso se pierde, lo hace el
   cron «Sifende: verificar estado de documentos» (cada 5 minutos).
3. Si el documento queda *Rechazado* o con *Error*, corrija el dato y
   pulse **Reintentar**. Un reintento tras una corrección usa una clave
   de idempotencia nueva. Si el fallo fue de conexión, se reintenta con
   la misma clave y no se duplica el documento.
4. En una nota de crédito o de débito, elija el *Motivo de emisión* en
   la pestaña *Facturación electrónica*. En una nota de remisión,
   indique también el responsable de la emisión y los kilómetros del
   recorrido.
5. Si SIFEN rechazó un documento y se cambió la fecha o el código de
   seguridad, Sifende pide inutilizar el número y emitir uno nuevo
   (*Facturación electrónica > Inutilización de números*).

La vista previa del XML y del QR no está disponible: Sifende no genera
documentos sin emitirlos.

Known issues / Roadmap
======================

- Proponer a ``l10n_py_edi_base`` las claves del diccionario que hoy
  agrega este módulo en ``sifende`` (motivo de emisión, unidad de
  medida, descuentos, email y código de cliente).
- Corregir en ``l10n_py_edi_base`` la lectura de
  ``account.authorization.l10n_py_establishment`` y de
  ``account_payment_term_line.days``, que no existen en 19.0.
